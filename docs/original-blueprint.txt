Knowledge Universe
Product blueprint v1.0 · Fully 3D AI Knowledge Explorer

Concept: A personal AI-powered knowledge universe where you explore technical subjects through interconnected, colorful, floating spheres in three-dimensional space. Every sphere represents a concept. Select one, and AI can explain it, generate deeper branches, identify related knowledge, or help you apply it to a real problem.

We'll use Recursio as the primary reference for how exploration should feel, but create a more immersive, three-dimensional experience with richer technical learning functionality.

Recursio's documented interaction model supports AI-generated child concepts, follow-up questions, descriptions, images, and spatial manipulation. Our additional 3D navigation, cross-domain linking, and technical learning tools are proposed features—not capabilities I'm attributing to Recursio.

2. 3D interactions and behavior










Select a sphere

Smoothly animate the camera toward it. Highlight direct connections, dim unrelated nodes, and display its description in the inspector.












Expand a concept

Generate 5–8 meaningful child nodes. New spheres emerge near the selected concept, then settle into the graph using a force-directed layout.












Explore relationships

Rotate, orbit, pan, and zoom in 3D. Double-click to focus. Select an edge to understand why two concepts are connected.

Critical UX rule: The universe should feel three-dimensional without making information difficult to read. Labels need distance-aware sizing, limited overlap, and a straightforward way to return to a known position. Camera motion must be optional and reduce when the user enables reduced-motion preferences.

The data model
Each node must be a durable record, not just an AI response with a label.
Example node

{
  "id": "node_transformers",
  "title": "Transformer Architecture",
  "domain": "ai_llms",
  "summary": "Attention-based neural network architecture",
  "difficulty": "advanced",
  "status": "generated",
  "tags": ["attention", "neural-networks"],
  "position": { "x": 120, "y": 45, "z": -80 },
  "pinned": false,
  "createdAt": "2026-11-15T12:00:00Z"
}
  


Illustrative record only. The implementation will generate actual IDs and timestamps.

The database should have these core entities:
Table	Purpose
universes	Separate saved knowledge universes
nodes	Concepts and their metadata
edges	Relationships between concepts
node_content	Explanations, examples, equations, code
sources	URLs, titles, excerpts, retrieval dates
node_sources	Evidence supporting specific nodes
expansion_runs	AI requests, model, cost, response and failures
learning_progress	Questions answered and concepts reviewed
camera_bookmarks	Saved viewpoints and exploration routes
settings	Models, preferences, performance options

Edges must have typed relationships, including prerequisite_of, part_of, used_by, related_to, and contrasts_with. A relationship should also store its source and confidence/evidence status.

This is important because AI may claim two concepts are connected even when the relationship is speculative.
5. How AI expansion will work
When you click Expand on a sphere:
1. Read the selected node, its immediate neighbors, domain, user question, and existing concepts.
2. Request 5–8 structured candidate concepts from the selected LLM.
3. Validate the output against a strict JSON schema, rejecting invalid IDs, unsupported relationship types, and excessively long content.
4. Match candidate concepts against existing nodes and reuse matching IDs where appropriate. Do not merge ambiguous concepts automatically.
5. Save new nodes and edges in a transaction, tagging the content as AI-generated until verified.
6. Animate new spheres into the existing 3D universe without resetting the camera or disturbing pinned nodes.

6. Performance targets for your PC
Your RTX 4060 and 32 GB of RAM are a reasonable development machine for this WebGL application. But GPU capacity alone doesn't determine graph performance: physics simulation, label rendering, draw calls, and React state updates can all become bottlenecks.

Proposed acceptance targets, to be measured rather than assumed:
Graph size	Performance target
50–100 visible nodes	Smooth 60 FPS interaction
250 visible nodes	45–60 FPS
500 visible nodes	30+ FPS
1,000+ stored nodes	Load focused neighborhoods rather than everything at once

To reach those targets, Codex should implement viewport-aware labeling, automatic settling of physics, adaptive pixel ratio, bounded animations, and neighborhood filtering.

Avoid permanent physics movement, heavy bloom effects on every sphere, or individual React re-renders on every physics tick. An actual 3D graph implementation has documented performance issues at a few hundred nodes when rendering patterns are inefficient.

7. Complete Codex development plan
I would divide this into six sequential milestones. Each milestone must produce working software with tests before Codex moves on.

Milestone 1 — 3D Universe Prototype

Build the complete dark interface and interactive 3D canvas, seeded with all six domains and roughly 60 sample nodes.

Acceptance: Smooth orbit, pan, zoom, click, focus, labels, search, and visible colored clusters. No backend or AI needed yet.




Milestone 2 — Persistent Graph Engine

Create the backend, SQLite schema, graph CRUD APIs, positions, pinned nodes, and saved camera viewpoints.

Acceptance: Add, edit, connect, expand, delete, save, and reload nodes without losing data. Reloading must preserve the graph.




Milestone 3 — AI Branch Generation

Connect a configurable LLM provider. Generate structured branches, explanations, and suggested relationships. Prevent duplicates and provide retries on failures.

Acceptance: Expand a real topic into meaningful child nodes, then expand a child a second time. All new concepts survive reload.




Milestone 4 — Technical Learning System

Add a proper node inspector with detailed explanations, code snippets, equations, analogies, notes, and follow-up questions.

Acceptance: Select a topic, learn it at multiple expertise levels, and save notes without leaving the universe.




Milestone 5 — Research & Knowledge Connections

Add source-backed web research, document references, relationship evidence, and automatic cross-domain suggestions.

Acceptance: View sources for an explanation and distinguish verified evidence from AI-generated hypotheses. No invented citations.




Milestone 6 — Optimization & Release

Benchmark rendering, add import/export, error recovery, keyboard navigation, camera bookmarks, backups, and production builds.

Acceptance: Pass automated tests, meet measured performance thresholds, export and restore a universe, and run locally without Codex.

Strategic design decisions
There are three decisions I'd lock in now.

First, 3D should be the actual interface, not decoration. Clicking, navigating, comparing, pinning, and following a relationship all happen within three-dimensional space. The inspector is there to present information that doesn't belong on a tiny sphere.

Second, the graph must be a learning system, not an idea generator. A normal AI mind map produces a lot of concepts but doesn't necessarily make you understand them. Our app should ultimately track prerequisites, explanations, evidence, learning progress, and connections between subjects.

Third, build an original implementation rather than reverse-engineering Recursio's backend. Your Codex + REA + Ghidra environment is valuable for other projects, particularly native software analysis, but doesn't provide a significant advantage for creating this particular browser-based graph. We already have mature open-source 3D libraries suited to the job.
Final recommendation
Start with Milestone 1 and make the universe visually excellent before connecting paid AI APIs. If the core navigation and graph don't feel right, more AI features won't fix the experience.

Once the first release is operational, the highest-value next feature is click-to-expand AI branching, followed by persistent saved knowledge and source-backed technical explanations.

The long-term differentiator is the ability to move naturally between your six subjects and discover genuine connections—for example, between Bayesian fault diagnosis, electronics troubleshooting, prediction modeling, and AI agent decision systems—inside one navigable knowledge universe.
